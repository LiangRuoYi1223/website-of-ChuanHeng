# 川衡登山协会 · 网站与功能接口

当前版本为 **V1.4 · 活动城市与足迹联动**。使用 React + Vite + TypeScript，保留已有页面与演示内容，并接入本地账号、权限和活动报名功能。接口由 Node.js 服务提供，账号、会话与报名记录保存到本地 SQLite 数据库。

## 打开网站

已安装依赖时，Windows 下双击项目目录中的 **启动网站.cmd**，或在此目录运行：

```powershell
npm run dev
```

然后在这台电脑的浏览器打开 <http://127.0.0.1:5173/>。`npm run dev` 同时启动网页（5173）和接口（3001），网页中的 `/api` 与 `/uploads` 请求会转发到接口服务。预览期间保持启动窗口打开；按 `Ctrl+C` 退出时会一起停止两个服务。电脑重启或服务停止后需要重新启动。

启动脚本会先检查 5173 和 3001 端口。提示端口被占用时，先确认并停止已有的开发服务，再重新启动，避免网页连接到另一套接口。已经运行的完整开发服务可直接通过上述地址访问。

需要分别启动时，在两个终端中运行 `npm run dev:web` 与 `npm run dev:api`；仅运行网页服务无法完成登录、后台保存和活动报名。

首次安装需要 Node.js 24 或更高版本，并运行 `npm install`。本地地址只在当前电脑上有效，公开访问需另行部署。

## 登录与权限

右上角「登录」按钮进入 `/login`；登录后的维护入口为 `/admin`。登录状态由服务端会话维护，敏感操作仍会在接口层校验权限。

| 身份 | 允许的操作 |
| --- | --- |
| 创始者（`founder`） | 修改网页所有内容，维护账号、角色和管理员权限。 |
| 管理员（`admin`） | 仅修改创始者开放的接口内内容；新建管理员默认没有内容编辑权限，后续由创始者授权。 |
| 社员（`member`） | 浏览公开网页，报名开放报名的活动。 |
| 浏览者（`viewer`） | 仅浏览公开网页。未登录访客同样只能浏览。 |

首次启动接口时会创建初始创始者账号，用户名为 `admin`，初始凭据保存在本机 `data/initial-admin.txt`，不会在网页或启动日志中显示密码。首次登录需修改密码，之后再管理账号或编辑内容。该文件含敏感信息，修改密码后应妥善移除。账号数据库位于 `data/chuanheng.sqlite`，上传文件位于 `uploads/`。管理员、社员和浏览者账号由创始者在后台创建。

从旧后台版本升级时，原 `admin` 角色迁移为创始者，原 `editor` 角色迁移为没有编辑权限的管理员；现有用户名、密码和会话保留。已有的 `data/initial-admin.txt` 仍记录原初始凭据；升级不会重新生成密码，也不要为获取新账号而删除数据库。

社员报名需满足：活动已发布、属于未来活动、已明确开放报名，且不是示例活动。未开放或过往活动只提供浏览。活动的 `registrationOpen` 默认关闭，正式活动确认后再开放；报名权限由服务端执行。

## 页面与交互

- **活动与足迹**：本学期出发日历、日期点击后左右分栏的活动速览、按类别／时间／体验组合筛选的活动预告、活动回顾、山野相册、中国足迹地图及公众号报名区域。
- **认识川衡**：组织介绍、四步首次出发指南、招新信息、普通活动 → 系统训练 → 队伍选拔 → 专业攀登的滚动成长路径。
- **川衡登山队**：训练方向、全部公开项目、单次攀登项目与全年训练合作说明，以及合作页入口。
- **合作**：资质资料、全部公开项目、支持方式与权益对照、四步合作流程、联系方式，以及页底可下载的合作手册。手册区使用真实 PDF 首页作为立体书封面。

动态效果包括影像视差、内容渐入与固定滚动章节。当前验收以电脑端为主。

视觉采用山野杂志主题：暖纸色、苔绿、麦黄，浅色故事标题使用思源宋体；登山队增加岩石黑与冰蓝。字体、字号、间距、圆角、图片比例和动效集中在 `src/design-tokens.css`，确认的规格见 [DESIGN_TOKENS.md](DESIGN_TOKENS.md)。字体使用本地文件，来源与许可见 `public/fonts/SOURCE.md`。

## 替换内容与素材

文案、活动和公众号入口的演示数据集中在 `src/demo-content.ts`。合作页文案、示例资质、权益、流程、联系方式与三个示例项目集中在 `src/cooperation-content.ts`，由 `demo-content.ts` 引用。这些文件用于静态演示与新数据库初始化；接口启动后，已保存的网站设置、活动和项目通过 `/admin` 修改。修改演示文件不会覆盖数据库中用户保存的内容。活动日期与回顾、资质人员与攀登项目目前均为明确标注的示例内容，正式资料待协会替换。

`PublicContent` 中的 `cooperation` 与 `projects` 已定义独立的数据结构。接口接通时，登山队页与合作页共用数据库中的公开项目列表；合作页其他文案仍来自静态配置。静态合作手册读取作者内容文件，不会自动读取数据库。数据库中的项目内容变更后，需将确认的内容同步到作者文件，再重新生成手册。

本学期日历的标题与日期范围在 `settings.semesterName`、`semesterStart`、`semesterEnd` 中设置；当前以 2026 秋季学期（2026 年 9 月至 2027 年 1 月）为演示。速览信息使用活动的 `duration`、`cost`、`meetingPoint`、`beginnerFriendly`、`registrationStatus` 字段。没有提供的信息会保持待公布状态。

活动预告可按 `category`、`timeCommitment`（`half-day`／`full-day`／`multi-day`）与 `experience`（`relaxed`／`scenic`／`skills`）组合筛选，分别对应半日以内／一整天／多日和轻松漫步／山野探索／技能练习。体验标签描述活动形式，具体参与要求仍由正式活动通知提供。

每次活动详情都有出发前准备卡，可在活动的 `preparation.notice` 与 `preparation.items` 中单独配置。条目包含 `id`、`title`、`description`。勾选显示当前核对进度，可以全部重置；状态只保留在当前页面，切换活动或刷新后清空。过往活动显示为准备清单回顾。

山野相册使用过往活动的 `album` 字段，每张照片配置 `id`、`src`、`alt`、`caption`、`isDemo`。页面预览前三张，灯箱可浏览全部照片，支持左右键、Esc 与焦点恢复。替换为真实照片时，也应更新说明与示意标志。

活动后台分别保存 `routeName`（宣传用路线名称）和 `cityCode`（活动所在城市），通过省份和城市下拉框选择地点，不需要填写经纬度。城市坐标表位于 `src/features/map-data/cities.ts`，定位不依赖联网查询。未选择城市的活动可保存，但暂不出现在地图上。旧记录的地点文字保留为路线名称，已有修改不会被演示数据覆盖。

中国足迹地图使用本地矢量素材，点位由 `src/features/footprint-data.ts` 按已发布活动聚合生成。同城活动共用一个点，点击后显示该城全部关联活动；活动回顾（`past`）显示绿点，活动预告（`upcoming`）显示蓝点，同城兼有两种活动时优先蓝点。演示活动的城市固定分配，点位与活动均有示意标记；删除、改城市或撤回活动后地图同步更新。几何与城市坐标的来源及生成方法见 [地图来源说明](src/features/map-data/SOURCE.md)。

图片位于 `public/images/`。可替换图片文件，或在后台修改对应的素材地址；作者演示素材地址在内容文件中设置。当前三张主图和一张相册同行图为 AI 生成示意影像；来源与完整生成提示见 [ASSETS.md](public/images/ASSETS.md)。山形标志为演示用原创 SVG。

公众号链接、二维码和合作联系方式尚未提供，页面保留待补充状态。二维码占位图不能扫描。

## 合作手册 PDF

合作手册读取作者文件中的 `demoContent`，与静态演示版合作页共用内容来源；接口接通后，网页项目列表读取数据库，手册仍需按下述步骤重新生成。当前手册为 8 页 A4 示例版：封面、组织与资质、三个独立项目页、支持与权益、合作流程、联系方式。全部示例项目都纳入手册；人员与资质明确标为示例，邮箱和微信保持待公布。

- 网站下载文件：`public/docs/chuanheng-partnership-handbook.pdf`。
- 同步输出副本：`output/pdf/chuanheng-partnership-handbook.pdf`。
- 网站书封面：`public/images/handbook-cover.png`，从最终 PDF 第 1 页渲染。
- 内容与文件校验：`public/docs/handbook-manifest.json`。

修改合作内容、项目或手册引用的影像后，运行：

```powershell
npm run handbook
npm run build
```

`npm run handbook` 读取现有内容，生成 PDF、首页封面和全部逐页预览，再更新 SHA-256 校验文件。`npm run build` 自动检查内容、项目影像、PDF 和封面是否同步；发现过期或缺失文件时会提示重建。普通构建只需要 Node.js 24，不需要 Python；只有重建手册时才需要作者依赖。

生成脚本为 `scripts/build-handbook.mjs` 与 `scripts/build-handbook.py`。它优先使用 Codex 提供的 Python，也支持通过 `CHUANHENG_PYTHON` 指定自己的 Python。其他环境可安装作者依赖：

```powershell
python -m pip install -r scripts/handbook-requirements.txt
```

PDF 使用嵌入的中文字体子集，阅读和下载无需安装字体。当前手册正文使用本机的 **HarmonyOS Sans SC**，封面标题使用 **SimSun（宋体）**，英文与数字使用缓存的 DM Sans；这与网站本地思源字体是两套不同的输出字体配置。原始网站字体为可变字体，未直接用其默认极细字重生成手册。字体选择记录在校验文件中；没有把系统字体文件发布到网站。

非 Windows 环境或需要另选字体时，把 `CHUANHENG_HANDBOOK_FONT` 设置为有中文覆盖、允许嵌入的静态 TrueType 字体路径。该字体用作作者环境的正文与无系统字体时的标题回退。建议使用静态思源或 Noto 中文 TrueType 字体；ReportLab 的作者脚本直接嵌入所选字体。

逐页图片位于 `artifacts/previews/handbook/`。生成器优先用 Poppler 渲染 PDF，未提供 Poppler 时使用 `pypdfium2`。每次重建均校验 A4 尺寸、页数，以及全部资质、项目正文、权益和流程条目，交付前还应检查这些逐页预览的版式。

## 构建预览

```powershell
npm run build
npm start
```

`npm start` 预览 `dist/` 中的构建结果，地址仍为 <http://127.0.0.1:5173/>，运行前需停止同一端口上的开发预览。托管平台需为独立页面配置回退到 `index.html`。

登录与报名同时需要接口服务。预览构建结果时，在另一个终端运行 `npm run start:api`；构建预览同样代理 `/api` 与 `/uploads` 到 3001。也可完成构建后仅运行 `npm run start:api`，由接口服务直接提供 `dist/` 网页，在 <http://127.0.0.1:3001/> 访问完整网站。公开部署需要配置 Node.js 服务、持久化数据与上传目录，以及 HTTPS 与正式站点地址；单独部署静态文件只包含公开页面。
