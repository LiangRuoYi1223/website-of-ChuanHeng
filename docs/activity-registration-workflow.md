# 活动报名与手动缴费管理

## 使用流程

管理员创建或编辑活动时填写“预设报名人数”，可选填缴费说明，按既有四时间规则开放报名。旧活动未设置人数时保持未知，不能接受新报名；仅修改旧活动说明不强行补造名额。

会员登录后报名，页面显示当前有效排位/名额，如10/5。按报名时间先后，名额内为入选，其余为候补。有人退出，后续有效报名顺次前移；退出记录保留。活动开始前可以退出，重新报名需要仍在报名窗口内，并排在当前队尾。

入选且未缴费者看到页面内缴费提醒和管理员提供的说明；候补不提示先缴费。当前不接支付平台，不自动确认收款、不自动退款、不发送外部通知。会员退出后原缴费状态保留，由管理员核实处理。

后台活动列表双击活动，或点击“报名管理”图标，打开该活动的报名面板。原编辑按钮继续编辑活动资料。报名面板按时间展示全部人员、排位、入选/候补/退出状态及已缴费/未缴费。管理员核实后切换缴费状态；服务端按旧值检查冲突，失败时不会假报成功。

## 日志与权限

报名、退出、重新报名、缴费状态变化和名额变化均追加日志，包含时间、对象、操作者UUID/名称、来源及变化前后值。来源模型保留self_service/manual/automatic，目前没有自动缴费入口。新事件从本功能启用时开始记录，过去未记录的退出或缴费变化不补造。旧报名仅从Auth回填新增姓名/邮箱展示列，原字段及原报名时间保留。网站没有日志编辑、删除或清空入口；普通用户和网站管理员的INSERT/UPDATE/DELETE/TRUNCATE都被数据库权限拒绝，事件只由受控业务触发器追加。历史日志维护仅留给Supabase平台的受信数据库管理权限，网站不接收或保存平台密码。不能修改或删除事件来伪造历史；删除无报名活动后仍保留事件和活动名称快照。

会员只读取本人记录和匿名汇总人数；完整名单、邮箱、付款及日志仅管理员可读。匿名Auth账号、伪造user_metadata管理员和直接表DML均不能绕过规则。报名、退出、付款及人数编辑按同一活动行锁协调；三个写接口绑定本次已确认的Auth UUID，阻止跨标签切换账号造成误操作。服务器时钟校验报名窗口，共享锁保证一次读取中的人数、容量与排位一致。

public.applications沿用原记录，新增registration_status、registered_at、payment_status、display_name、email列；原payload/created_at不改写。新增public.registration_events。public RPC均SECURITY INVOKER，private schema中的最小SECURITY DEFINER助手独立校验身份/角色/目标，固定search_path并撤销默认授权，不提供通用提权能力。原chuanheng数据、活动路线快照及封面不变。

## 验证

- 网站完整回归、本人/管理员服务和DOM交互测试。
- scripts/validate-registration-sql.mjs与原validate-activity-route-sql.mjs在隔离PG17/PG18运行完整迁移链，覆盖队列、重报、日志、旧值冲突、匿名Auth、直接DML、伪造权限、名额清空和旧记录保留。
- 本地浏览器合成数据视觉验收不会写入生产。
- 尚未以两个真实数据库连接实测锁等待竞争，也未连接真实支付或自动调整。
