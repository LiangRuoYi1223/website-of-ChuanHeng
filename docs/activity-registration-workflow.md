# 活动报名、缴费记录与人工核实

> 历史实现与发布记录。2026-11-01新增会员资料、保险和自动清理后的当前规则见 [会员保险及资料清理](member-insurance-retention-workflow.md)，该文档优先；下文旧日志页签、3 MiB新上传及永久图片保留描述仅记录当时行为。

## 使用流程

管理员创建或编辑活动时填写“预设报名人数”，可选填缴费说明，按既有四时间规则开放报名。旧活动未设置人数时保持未知，不能接受新报名；仅修改旧活动说明不强行补造名额。

会员登录后报名，页面显示当前有效排位/名额，如10/5。按报名时间先后，名额内为入选，其余为候补。有人退出，后续有效报名顺次前移；退出记录保留。活动开始前可以退出，重新报名需要仍在报名窗口内，并排在当前队尾。

管理员在「服务配置」统一上传和保存全站微信收款码，所有活动共用。入选且未缴费者点击「缴费」查看真实收款码，上方提示「付款时请备注姓名」；点击「我已缴费」后选择并提交缴费记录图片。只有图片上传与受控提交都成功才显示蓝色「应已缴费」，等待管理员核实。候补不提示先缴费，已缴费者不能自助降级或重复提交。当前不自动确认到账、不自动退款、不发送外部通知；会员退出后缴费状态保留。

后台活动列表双击活动，或点击“报名管理”图标，打开该活动的报名面板。原编辑按钮继续编辑活动资料。报名面板按时间展示全部人员、排位、入选/候补/退出状态及未缴费（白）／应已缴费（蓝）／已缴费（绿）。名单增加缴费记录入口，可查看最新和历史图片。管理员核实后手动切换三态；服务端按旧状态及最新凭证ID检查冲突，失败时不会假报成功。查看历史图片时不能直接审核该行，须切回最新记录。

## 日志与权限

报名、退出、重新报名、缴费记录提交、缴费状态变化和名额变化均追加日志，包含时间、对象、操作者UUID/名称、来源及变化前后值。来源模型保留self_service/manual/automatic，目前没有自动缴费入口。新事件从本功能启用时开始记录，过去未记录的退出或缴费变化不补造。旧报名仅从Auth回填新增姓名/邮箱展示列，原字段及原报名时间保留。网站没有日志编辑、删除或清空入口；普通用户和网站管理员的INSERT/UPDATE/DELETE/TRUNCATE都被数据库权限拒绝，事件只由受控业务触发器追加。历史日志维护仅留给Supabase平台的受信数据库管理权限，网站不接收或保存平台密码。不能修改或删除事件来伪造历史；删除无报名活动后仍保留事件和活动名称快照。

会员只读取本人记录和匿名汇总人数；完整名单、邮箱、付款及日志仅管理员可读。匿名Auth账号、伪造user_metadata管理员和直接表DML均不能绕过规则。报名、退出、付款及人数编辑按同一活动行锁协调；所有报名、凭证提交和审核写接口绑定本次已确认的Auth UUID，阻止跨标签切换账号造成误操作。服务器时钟校验报名窗口，共享锁保证一次读取中的人数、容量与排位一致。

public.applications沿用原记录，新增registration_status、registered_at、payment_status、display_name、email列；原payload/created_at不改写。新增public.registration_events。public RPC均SECURITY INVOKER，private schema中的最小SECURITY DEFINER助手独立校验身份/角色/目标，固定search_path并撤销默认授权，不提供通用提权能力。原chuanheng数据、活动路线快照及封面不变。

## 活动页分区侧栏（2026-11-01）

活动信息采用「活动资料／报名详情」页签。顶部展示简短路线指标、地点和开始时间，底部展示本人状态与排位/名额，报名、重报、退出与重试使用同一份已验证账号状态。入选且未缴费时提供「缴费」，打开微信收款码和记录提交窗口；本网站不代用户执行付款。切换页签不重复挂载报名服务。

桌面侧栏吸附，长资料在中间滚动；高度不超过600px时允许整卡滚动，保证短屏所有操作可到达。手机底部入口打开模态面板，关闭恢复焦点与页面滚动。登录返回 #application 自动展开报名详情。仅活动页面使用新布局，路线与资讯侧栏不变。本次无需数据库迁移。


## 全站收款码与私有缴费记录（2026-11-01）

全局配置位于`/admin/services`（兼容`/admin/settings`），不是每活动配置。管理员上传非空JPEG/PNG/WebP最多3MiB，经既有封面后端转WebP，确认正确后保存全站收款码；图片等比完整显示，改码不覆盖或删除旧对象。未提供真实码时明确提示未配置，不生成示例码。

缴费记录原图最多8MiB，只接受JPEG/PNG/WebP，后端真实解码、最大4000万像素/12000px，保留文字到最大4096px并去元数据，最终私有WebP不超过3MiB。`payment-proofs`仅本人和管理员可读，页面通过授权download生成Blob URL，关闭或切账号撤销；网站不创建公开凭证链接。客户端仍仅publishable key与用户JWT。

新凭证仅限本人有效入选且unpaid。pending期间等待核验，管理员退回unpaid后才能追加新记录。相同当前对象重试幂等；上传成功但RPC未确认时保留stagedPath供当前文件重试，不假报成功也不删图。最终RPC重验当前排位、身份、状态、旧凭证及Storage真实对象。管理员审核同时比较旧状态与proof ID，防止状态退回又重交造成旧图审核新记录。

`application_payment_proofs`和`payment_settings_events`与报名日志均禁止网站INSERT/UPDATE/DELETE/TRUNCATE（插入仅受控函数/触发器）。`set_activity_registration_payment`升级五参数，旧四参数入口移除；新增`submit_activity_payment_proof`、`get_payment_settings`、`save_payment_settings`受控接口。凭证外键保护历史关联，含凭证的账户不能直接级联删除，需受信平台维护。无自动支付回调或到账识别。
