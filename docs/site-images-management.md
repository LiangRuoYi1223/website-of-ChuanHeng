# 全站图片与背景管理

管理员进入 `/admin/backgrounds` 后，可以上传并保存首页轮播，以及活动、路线、影像、资讯、关于、足迹、加入、登录页面的背景与配图。

首页图片可添加、移除、上移、下移，不再固定三张。至少保留一张；只有一张时前台不显示切换按钮。添加时先以原有雪山图占位，可立即上传替换；修改直到点击“保存全站图片”才会公开生效。

每张图片可填写图片说明和来源/署名（各最多 200 字）。内置 `/images/redesign-v2/` 图片始终保留 AI 示意标识；上传新图时清空原图的来源，管理员应填写新来源。替换背景不代表发布真实活动或协会记录。官方圆形徽章继续使用原图。

活动、路线、影像、资讯中的具体内容图片，在对应管理编辑器修改。路线与资讯支持上传压缩和已有图片地址；已有内容封面优先于背景管理中的默认封面。全站收款码仍由服务配置维护，私有缴费凭证仍由报名流程管理。

上传沿用现有 `/api/covers/process`：同源校验、服务端管理员校验、Images 压缩为 WebP，再以新文件名写入 `activity-covers`。JPEG/PNG/WebP 原图最多 3 MiB；失败保留原图，不回退未经处理的源文件，不覆盖或删除历史文件。权限和存储规则沿用既有配置。

公开前台按需读取配置，并在窗口重新获得焦点或当前窗口保存成功后刷新；加载失败继续显示可用图片。坏图使用暗色占位，避免重复重试。多管理员/窗口保存冲突时保留当前编辑，不覆盖新版本；需要整理未保存说明后重新加载。自动续期应保留同一管理员的编辑；退出、切换账号、降权应清理编辑界面并丢弃迟到响应。

## 本地预览

普通设计预览读取独立浏览器图片设置，保存按钮为“保存本地图片”，不写云端。开发环境使用 live 内容时，可在 `/admin/backgrounds?preview=1` 编辑，再通过“打开网站”进入 `/?preview=1` 检查；查看其他页面时也可加 `?preview=1`。生产构建忽略预览参数。预览图片最多 1 MiB，浏览器容量不足会明确提示且不替换原配置。

## 发布前置与验证

增量迁移 `supabase/migrations/20261105054246_site_image_settings.sql` 已于北京时间 2026-11-05 应用到正式项目，文件编号与云端迁移记录一致。后续发布先核对迁移历史，不得重复执行，也不要重新执行初始化 SQL。

- 新公开单例仅包含图片配置和版本时间，公开只读。
- `get_site_images()` 返回 `{config, updatedAt}`，未配置时 `{}` 回退至内置图片。
- `save_site_images(p_config, p_expected_updated_at, p_expected_user_id)` 绑定可信管理员 UUID，锁行比较原始时间，冲突 `40001`。
- 轮播使用稳定 ID，配置总体最多 128 KiB。图文来源写在配置中；更改仅追加私有审计，网站角色无审计访问权限。
- 不改变旧 `chuanheng`、活动、路线、报名和收款设置，不引入新服务端密钥或存储桶。

验证命令：`npm test`、`npm run build:production`，以及 `node --test scripts/validate-site-images-sql.mjs scripts/validate-member-insurance-sql.mjs`。SQL 验证使用 ignored `artifacts/sql-validation` 内的隔离 PGlite 引擎，缺失依赖时会失败，不自动跳过。云端联调和真实浏览器视觉验收需要另行记录。
