# 前后台共同登录状态修复

**目标：** 管理员返回网站时显示已核实的登录状态，并能同时保留后台与网站标签页。

**原因：** `backend.js` 已开启会话持久化；网站 Header 却固定显示「登录 / 注册」，而后台单独验证登录状态。

**边界：** 本任务在独立 worktree 实现，只在 App.jsx 替换两处登录入口、在 Admin.jsx 修改一个网站链接，其余逻辑写入独立组件与独立测试。不得改动另一对话正在开发的个人设置、报名、保险与资料清理功能。不改数据库、现有登录重定向与后台授权。

**实现：** 公共导航沿用同一 Supabase 客户端，启动时读取会话并向 Auth 验证身份；订阅登录、退出、刷新、账号更新事件。回调同步退出后再请求身份，使用版本号丢弃过时结果；退出时立即清除显示。验证中与失败时明确显示状态。已核实管理员可从新标签页打开后台，后台可从新标签页打开网站。身份显示不授予任何权限。

**步骤：**

- [x] 编写真实 App 导航回归测试，先证明已登录管理员仍看到登录入口。
- [x] 新增公共登录导航组件；替换两个入口；修改后台网站链接。
- [x] 验证刷新恢复、跨窗口事件、退出及竞态、普通会员伪造 metadata 不显示后台入口。
- [x] 运行对应测试、全套测试与生产构建，独立审查，核对另一目录未被修改。

**后续合并：** 另一对话将增加用户名和个人设置入口。合并时保留其完整导航功能，沿用这次会话恢复/事件同步行为，不用整文件覆盖。
