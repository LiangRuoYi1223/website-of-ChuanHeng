# 全站图片管理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax for tracking.

**Goal:** 后台背景管理可以保存各页面图片和任意数量的首页图片，支持上传、增删和排序。

**Architecture:** 独立站点图片单例配置（heroSlides 与 slots），公开只读，管理员通过带版本校验的 RPC 保存。上传复用管理员校验及 Images 压缩的现有封面服务；旧图片不覆盖、不删除。React Context 给全部页面共享配置；本地预览独立存储，不写云端。

**Tech Stack:** React 19、Vite、Supabase Postgres/RLS、现有 Cloudflare Images。

**Spec:** 本文件包含本次需求与设计：背景管理覆盖活动、路线、影像、资讯及其余固定配图；首页保留至少一张，可增删及上下排序，不固定三张。每张图片可填写说明和来源，内置 AI 图保留标识。官方徽章保持原图。内容记录封面在对应编辑器管理，路线和资讯补上上传。空配置沿用内置图，读取失败保留可用图片；配置冲突保留未保存输入，不强行覆盖。

## Global Constraints

- 简体中文，保留黑白、品牌橙和官方原色圆形徽章。
- 不改旧 chuanheng 数据，不改报名、收款码、个人设置或发布文件。
- 不提交密钥、用户数据、运行日志、node_modules、dist、artifacts。
- 实现阶段不触发部署；数据库增量迁移先在隔离引擎验证。用户后续明确授权“上线”后执行发布流程。

## Review Focus

- 删除当前首页图片后仍有有效选中图；大量图片在手机上可操作。
- 换图或保存时退出、切换账号，迟到响应不能回写状态。
- 多后台窗口保存冲突不得丢失输入。
- 上传失败保留原图，不回退原文件上传。
- 配图及 AI 标记来源一致，正式记录不受背景替换影响。
