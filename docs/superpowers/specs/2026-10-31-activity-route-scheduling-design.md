# 活动时间与路线选择方案

## 用户要求

活动编辑器提供报名开启、报名截止、活动开始、活动结束时间。GPX/KML 文件统一由路线管理上传，活动选择已有路线，不再单独上传轨迹或自动创建重复路线。

## 页面与操作

- 活动表单保留当前深色、品牌橙及官方徽章，增加两组精确到分钟的时间输入：活动开始/结束，报名开启/截止。
- 保留“开启活动报名”总开关。开启后按报名时间窗口接收申请；到截止时间、活动开始或活动结束后关闭申请，服务端同时执行判断。
- 新建活动和编辑活动使用路线选择器，显示路线名称、地点、里程及可用轨迹状态，提供“打开路线管理”和“刷新路线列表”。打开路线管理时保留当前活动填写内容。
- 路线管理成为唯一轨迹上传界面。旧 `/routes/import` 地址导向路线管理，活动编辑器移除上传区及“关联路线名称”自由输入。
- 草稿允许尚未填齐时间或尚未关联路线；发布时要求有效活动起止时间。开启报名时要求完整报名窗口。前台详情展示四个实际设置的时间。

## 时间规则

- 字段为 `registrationStart`、原有 `registrationDeadline`、`dateStart`、新增 `dateEnd`。界面按使用者本地时区填写，保存为含时区的 ISO 时间。
- 活动结束晚于开始；报名开启早于截止；报名截止不晚于活动开始。
- 保存历史活动不强制报名截止仍在未来，避免截止后无法修改介绍。实际接收报名依赖数据库当前时间。
- 旧记录的日期、缺失时间及历史状态保留，不推造报名开启或活动结束时间。缺失完整报名窗口的记录不接收新报名，补齐后可正常开放。

## 路线关联与历史数据

用户已确定采用路线管理统一维护、活动选择路线的方向。继续保留活动直接上传会违背此要求，因此不采用。

用户已确认：保留活动选择时的轨迹快照及地点/里程/海拔；路线之后更新不改写已经记录的活动历史。活动明确改选路线时才更新快照。另一种选择是所有关联活动同步最新路线，代价是历史地图也随之变化，本次不采用。

- 已有活动自带的轨迹、自动生成路线、去重归档和审计原样保留；不重复导入、不迁入示例、不删除旧私有数据。
- 新活动从所选路线取得轨迹与参数，不创建自动路线；地图、分段海拔、关联路线和符合条件的足迹继续可用。
- 路线删除、归档、去重及跨标签页编辑均重新检查活动引用；不允许留下悬空关联。数据库也保护直接写入路径。
- 现有活动轨迹保存 RPC 会修改自动路线，不能直接复用于新流程。使用针对性迁移引入路线选择保存流程，调整旧调用及删除清理依赖；不重跑初始化 SQL。

## 验收

自动测试覆盖路线选择与复用、缺失/归档路线拒绝、既有轨迹保留、历史版本行为、关联删除保护、跨窗口冲突，以及四个时间的顺序和报名边界。隔离 PostgreSQL 实际执行新迁移、RLS 与 RPC；全套测试、正式构建及 Worker 无 Node 外部依赖打包通过后，再按本次既有发布和 GitHub 同步授权完成上线与核对。

生产校验不发布合成协会内容；测试事务回滚。诚实区分自动测试、真实接口联调与实机视觉检查。

## 用户追加范围

用户随后明确要求创建活动时可独立上传照片，并修复首页卡片坏图、里程精度和缺失海拔显示。已纳入本次实现：JPEG/PNG/WebP 最大5MiB、管理员目录Storage上传；首页/列表/详情共用封面降级；两位里程小数，未知海拔不显示空单位。
