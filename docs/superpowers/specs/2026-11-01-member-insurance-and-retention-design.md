# 报名保险资料、到期清理与个人设置设计

状态：已按用户2026-11-01逐项修订的最终规则实现并发布；验收及边界见PRODUCTION-HANDOFF。

## 目标和已确定规则

在现有报名排队、全站微信收款码和人工核实缴费的基础上，收集购买保险及活动紧急联系所需资料，提供管理员导出、保险登记及限期清理。个人设置承载会员自行保存的账户资料。

用户已明确：

- 报名弹窗收集真实姓名、身份证号、手机号；手机号默认填入个人设置中已保存的号码。
- 用途说明为「身份证号收集用于社团帮社员统一购买保险；手机号收集用于活动中的紧急联系。」
- 管理员能下载姓名、身份证号、手机号组成的 Excel。
- 每条报名保险状态默认「未购买」，管理员确认「已购买」前须再次确认。
- 手动清理身份证号和活动手机号须两次确认；活动结束后清理全部活动身份证号、活动手机号和缴费图片，最迟活动结束日期次日完成。
- **只清理本次活动收集的资料；个人设置中保存的手机号保留。**
- 本次报名确认的真实姓名作为报名/保险历史中的姓名快照保留；用户要求删除的字段范围为身份证号、活动手机号及缴费图片，不删除人员和操作历史。
- 操作日志仅留在 Supabase；移除网站后台报名管理的「操作日志」页签及对应读取接口权限。日志仍不可通过网站修改、删除或任意伪造。
- 缴费图片最终保存上限为 1 MiB，超出目标的原图自动压缩。
- 用户名左侧用白、蓝、绿圆点分别表示未缴费、应已缴费、已缴费，状态文字统一白色。
- 登录后右上角显示用户名，点击进入用户设置，包含用户名、真实姓名、手机号、邮箱及活动记录。

## 方案与约束

采用「长期账户资料 + 活动临时资料 + 受信后端清理队列」。这是满足上述保留边界的方案：账户手机号具有独立用途和保存操作，活动副本具有明确清理期限。身份证只进入活动临时资料。

已排除的做法及原因：

- 将身份证、活动联系方式写进 Auth metadata、通用活动 JSON 或不可删日志：会产生难以按活动清理的额外副本。
- 只在浏览器关闭页面或管理员访问时清理：无法保证无用户访问时仍执行。
- 仅删除 Storage 元数据：Supabase 要求使用 Storage API 删除真实文件，直接 SQL 删除会遗留文件。
- 删除整条报名或账户：会丢失报名、缴费、保险及活动历史，不符合保留操作结果的目标。

沿用现有 React/Vite、Cloudflare 图片处理及 Supabase 身份/权限。旧 chuanheng 数据和历史内容不迁移、不修改；已执行迁移不改写，新增针对性迁移。

## 会员个人设置

- 新增本人专用资料页，桌面右上角及手机菜单在已核实登录后显示用户名入口。未设置用户名时显示「个人设置」，不展示 UUID。
- 用户名、真实姓名、个人手机号可由本人保存；真实姓名和个人手机号均可不长期保存，报名时仍须填写完整活动资料。
- 个人设置不显示邮箱、不提供邮箱修改。邮箱仍用于既有Auth登录及邮箱确认，本次不改变登录方式，也不新增独立邮箱字段。
- 资料按 Auth UUID 绑定；普通会员只可读写本人资料。资料字段不用于授予管理员权限，管理员权限继续依据受信角色。
- 活动记录来自本人的报名历史，包含标题、日期、报名/退出、入选/候补和缴费状态；已结束活动仍可查看非敏感记录。当前没有签到数据，页面不声称已实际到场。
- 活动归档或取消发布后，本人历史记录仍有必要的活动标题和时间，不依赖仅返回公开内容的列表。
- 注册成功后不强制跳过邮箱确认，也不为旧账号补造真实姓名或手机号。

## 报名弹窗

- 点击报名/重新报名先打开资料弹窗，填写真实姓名、身份证号、手机号，并主动勾选用途及保存期限说明；未提交弹窗不产生报名。
- 真实姓名和手机号从已保存的个人资料预填，可为本次活动修改；身份证不从个人设置预填、不存长期资料。
- 个人资料加载完成后再预填，晚到的响应不得覆盖用户已输入内容；加载失败时允许明确提示后手动填写，切换账号必须清空上一账号内容。
- 修改本次活动资料不会自动覆盖个人设置；个人资料后续修改也不会改写本次报名已经确认的姓名和联系方式。
- 用途说明和清理时间紧邻字段，手机号说明纠正原输入中的笔误。身份证输入支持末位小写 x 并规范为 X，服务端校验中国大陆18位身份证的格式、日期及校验码；手机号按中国大陆11位手机号格式校验。格式校验不宣称核验了真实身份。
- 新资料与报名排队在同一服务器事务中保存；排位仍以服务器成功报名时间为准。旧二参数报名入口关闭，旧客户端不能绕过必填资料。
- 新增独立活动临时资料表，只经本人/管理员专用受控接口访问；普通名单和定时轮询不携带完整身份证、手机号。
- 当前旧报名保持原排位、时间和缴费状态，显示「保险资料待补全」。本人可在活动结束前补全资料，不需要退出重报。
- 本人补充或更正资料需重新确认用途；已登记购买保险后禁止自助改保险姓名/身份证，先由管理员退回未购买后更正，避免保险与新资料不符。
- 本轮延续退出、重报的既有队列行为；退出者资料可在活动结束前保留用于必要的保险/退款处理，导出默认不包含退出者。重报必须重新确认资料。
- 表单关闭、退出登录或切换账号时清空内存中的敏感输入，不写 localStorage、URL、日志、测试产物或异常详情。

## 后台报名管理及 Excel

- 移除「操作日志」页签。保留名单、汇总、缴费审核，增加保险状态、保险资料完整性、Excel 导出和清理状态。
- 名称优先显示本次确认真实姓名，辅以用户名/邮箱；姓名左侧显示缴费状态圆点。所有缴费文字白色，并保留文字含义以供读屏辨识。
- 保险状态独立于缴费状态，为「未购买／已购买」，默认未购买。管理员选择已购买后显示姓名和活动的确认弹窗，取消不写入。
- 只有有效入选且资料完整的人员可被登记为已购买。管理员可手动退回未购买，全部变更记录身份、时间及前后状态；服务端核对旧状态防止覆盖他人修改。
- 名额调整/退出不自动撤销已经记录的保险或缴费结果；需要管理员核实处理。
- Excel 仅导出有效入选者，附保险状态；不导出候补/退出者。缺失资料单独明确提示，不编造号码。
- 实际生成 .xlsx，姓名、身份证号、手机号均为文本单元格，保留18位号码和前导零，禁止把用户字符串解释为公式。
- 点击导出时专用管理员接口才读取完整资料；在浏览器内生成文件，不在服务器存导出副本，完成后释放敏感内存及 Blob URL。
- 导出处说明仅用于本次活动保险及紧急联系，下载至管理员设备的文件须由管理员自行清理，网站无法远程撤销本地文件。

## 缴费图片与状态颜色

- 原图继续允许非空 JPEG/PNG/WebP，最多8 MiB，使1–8 MiB文件可自动处理；后端真实解码、限像素、去元数据、逐档压缩至 WebP **不超过1,048,576字节**。
- 无法压至上限时明确失败，不回退上传原图。提示为「自动压缩至1 MiB以内，原图最多8 MiB」。
- 前端输出校验、服务端处理、Storage bucket 和最终提交 RPC 同步采用1 MiB新上传门槛。
- 历史1–3 MiB缴费图片在未清理前仍允许授权查看，上传与历史下载上限分别处理。
- 新图仍只有本人有效入选且未缴费时可交；上传与受控提交成功才进入应已缴费。管理员审核仍同时核对旧状态和最新凭证ID。
- 活动结束或进入清理状态后禁止新图上传、提交、替换和查看；全部历史图及已上传但提交未完成的对象均在清理范围内。
- 活动页和后台的缴费文字统一白色；明确的白/蓝/绿颜色仅用于状态圆点。保险不用该三色冒充缴费状态。

## 清理时间、手动确认和执行

用户最终确认的自动与手动清理规则：

- 以北京时间和服务器已确认的活动结束时间为准。活动结束即关闭敏感资料/缴费图片读取与新增入口，自动清理每3分钟一轮，持续进行直到连续两轮核验通过；失败不得停止。
- 每轮先清除身份证号、活动手机号及全部缴费图片，再核验数据库和Storage实际剩余对象。首次核验为空后，至少间隔一轮（3分钟）再次核验；再次为空才完成并停止该活动的自动任务。若第二次发现残留、发生错误或出现新数据，恢复清除、重置连续通过计数，继续后续轮次。
- 管理员手动清理入口从活动报名开启时间起可用；第一步确认活动与资料数量，第二步明确「永久删除活动身份证号、活动手机号及缴费图片」后提交。个人设置手机号及操作日志不在范围内。清理期间暂缓本活动资料/图片写入，完成后未结束的活动继续接受符合报名窗口的新报名和主动补资料，旧数据不恢复。
- 自动到期清理依据已确认的保存期限执行，不等待管理员点击两次确认。
- 活动结束时间缺失的旧记录不推测期限；后台标明「清理时间待确认」，须补齐活动结束时间才能可靠自动清理。新活动继续强制有效结束时间。
- 自动到期清理一旦开始，延长/修改结束时间也不会恢复资料或重新开放资料收集。手动清理完成且活动尚未结束时可重新主动收集新资料，不能把重新填写称为恢复已删除资料；历史显示相应清理状态。
- 使用数据库状态和受限队列先封存、硬删除存放身份证号和活动手机号的临时行，报名表中的姓名快照、报名结果、保险与缴费状态保留；再由受信 Edge 执行器通过 Storage API 批量删除该活动所有历史及未关联缴费对象。失败留待重试，未完成不得显示已完成。
- 清理与上传/资料保存互斥，封存后阻止迟到上传成功。范围仅限 payment-proofs 中该活动报名对应前缀，禁止清空整个桶或影响其他活动、收款码、封面和影像。
- 凭证保留不含文件的ID/提交时间/已清理标记，以维护原缴费结果及审计关联；移除文件地址，实际图片真实删除。身份证、活动手机号不在墓碑中保留。
- Edge 使用平台受信服务身份，只能领取服务器判定到期或管理员完成确认的清理任务。定时唤醒不接收用户提供的活动、文件路径或bucket，不把服务密钥复制到浏览器或Cloudflare公开配置。
- 队列限批、带租约、幂等、重入去重及失败重试；网站后台报名管理显示清理进度与手动重试，详细故障及审计留在Supabase，遵循用户不在网站显示日志的要求。
- 保留清理发起人/automatic、时间、范围及数量、成功/失败结果的追加日志。网站不能读取历史日志页签，也不能修改、删除或伪造日志。

### 删除边界

网站提供活动数据库资料硬删除和 Storage API 真实删除，不提供恢复入口。不得宣称网页删除会同步抹除 Supabase 历史数据库备份、数据库底层介质或管理员已经下载的 Excel。若平台恢复历史备份，必须先运行到期清理并验证完成再恢复网站敏感数据访问；被 Storage API 删除的文件不随数据库备份恢复。

## 权限与历史兼容

- 所有资料、保险、导出、清理操作绑定已核实Auth UUID；敏感接口必须真实身份校验。匿名Auth、伪造user_metadata角色、跨账号切换均不能访问。
- 完整资料仅本人受控表单及可信管理员专用导出可读；活动公开接口只返回非敏感汇总。
- 永久日志不记录身份证、手机号、导出内容或图片二进制。审计只记录业务ID、允许的身份快照、状态和数量；网站撤销日志读取权限，保留受控业务写入。
- 旧报名、原时间、排位及缴费结果保持；旧记录不补造资料、保险购买或历史操作。旧payment proof按其活动结束期限同样清理。
- 不把全站收款码或协会照片误当缴费图片清理，不删除账号或整个活动；已执行迁移及旧系统记录不改写。

## 验证与发布标准

- 隔离PG17/18验证完整迁移链、旧数据保留、强制报名资料、本人/管理员权限、保险旧值冲突、事件无敏感值及网站无日志权限。
- 清理覆盖自动到期、两次确认取消/失效/账号变化、批次重试、Storage API失败、全部历史及未关联对象、活动互不影响、活动改期及旧记录缺时间。
- Excel逐字校验18位身份证、手机号及中文，防公式执行；清理后导出不可回读已删除资料。
- 图片真实处理验证1–8 MiB原图自动处理、新上传不超1 MiB、历史图兼容、处理失败不回退；保留现有付款旧状态及proof ID并发保护。
- 表单、用户设置、登录后导航、导出、保险确认、圆点/白字、资料清理界面做DOM交互测试及可用的桌面/手机实机验收。
- 全套网站测试、正式构建、Worker无Node外部依赖打包；发布前独立安全及功能审查。
- 云端应用迁移、部署Edge清理任务和定时计划后验证权限/计划及无敏感内容的运行结果，保留现有真实内容/报名计数和原字段哈希证据。合成身份证、手机号和缴费图不写入生产。
- 明确区分自动测试、本地图片处理、浏览器实机和云端真实联调；未提供真实资料不宣称验收真实保险购买或真实支付。
