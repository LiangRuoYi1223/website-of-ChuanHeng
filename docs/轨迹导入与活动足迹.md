# 轨迹导入、活动足迹与 Debug

## 当前使用方法（2026-10-31）

1. 登录后台，在“路线管理”新建或编辑路线，上传 GPX/KML。系统自动计算里程、爬升；无法计算时弹窗提示管理员补充，也可选择“暂不提供”。未补充的指标公开显示“暂不提供数据”，Debug 列出缺失项并可直接打开路线编辑。
2. 在“活动管理”新建或编辑活动，选择已保存路线；可打开路线管理并刷新选择列表，不必重复上传。
3. 设置活动开始、结束时间；需要报名时开启报名并设置报名开启、截止时间。新公开活动填写有效起止时间，报名截止不得晚于活动开始。
4. 在“活动封面”独立上传 JPEG、PNG、WebP（正式站原图最大 3 MiB）。后端核验管理员身份后自动压缩为 WebP，最长边 1920 像素、保留比例，不放大；压缩失败不上传原图。保存活动；需要公开时勾选“发布到云端内容表”。
5. 活动保留选择时的路线历史版本，后续路线修改不会改变它的地图和指标；活动表单只读展示路线参数。人工补充单独记录管理员来源，不改写原始统计或补造海拔曲线。符合条件的已结束活动生成足迹，缺失海拔和未识别省市保持未知。

旧 `/routes/import` 已统一跳转路线管理。现有活动自带轨迹、原自动路线和审计均保留；没有的新时间不自动编造，补齐后才开放新报名。最新迁移为 `20261031142417_route_manual_metrics_and_cover_limit`，发布及验证见 [生产交接](PRODUCTION-HANDOFF.md)。以下早期流程保留作历史记录，不是当前上传入口。

本功能已完成本地实现与验证。Supabase 迁移 `20261031074956_chuanheng_v1_content_and_tracks` 已成功应用，Cloudflare 已部署版本 `9c159570-c589-4813-9dfb-6f819479d40e`，公网 HTTP 验收通过。没有导入示例或写入协会真实活动。当前交接见 [生产交接](PRODUCTION-HANDOFF.md)。

## 现在如何使用

1. 打开 http://127.0.0.1:5178/admin/activities?preview=1 ，新建或编辑活动。
2. 选择 `.gpx` 或 `.kml` 文件。后端自动解析轨迹、计算统计并识别省市，页面立即显示结果。
3. 所有线段显示在同一张地图，段与段之间保持断开；每段单独显示海拔剖面、里程、累计爬升和下降。每段的距离横轴均从 0 km 开始。
4. 填写活动名称、开始日期及活动状态。已结束、有日期、有轨迹的活动保存后，自动出现在本地足迹预览，并生成关联路线；不需要另建足迹。
5. 在 http://127.0.0.1:5178/admin/debug?preview=1 检查重名路线。核对来源、统计及关联活动，明确选择保留版本后处理。其他版本归档，活动关联转向保留路线，各活动自己的原始轨迹结果仍保留。

单独试用文件转换可打开 http://127.0.0.1:5178/routes/import ，转换后可下载 GeoJSON 或完整 JSON，或保存路线草稿。路线管理的预览按钮可打开草稿详情，刷新后仍可从同一浏览器读取。

浏览器草稿不等于公开发布。本地数据分别存在 IndexedDB（完整轨迹）和 localStorage（内容与关联摘要），清除网站存储会丢失。重要结果可先导出。

## 自动定位和足迹

后端使用真实行政区面离线匹配，逐个检查文件记录的坐标；不把用户轨迹发送给在线逆地理服务。保留各段经过的已确认省市，足迹代表坐标取实际第一个点。

境外、数据未覆盖、边界附近或重叠位置会返回“未匹配/部分匹配”，不按最近城市猜测。Debug 列出需核实地点的活动。城市名称按来源的市级/地级及省直辖单元保留。

源文件、边界版本、坐标转换、500 米边界保守排除带及授权范围见 [行政区数据来源](../server/geography/SOURCE.md)。该数据适用于当前本地学习预览；公开上线前需要确认适用授权或替换边界数据。下载时间不代表所有边界都是最新版本。

## 文件支持与计算规则

- GPX：`trk/trkseg/trkpt`，无有效轨迹时读取 `rte/rtept`；独立航点不混成路线。
- KML：`LineString`、`MultiGeometry`、`gx:Track`、`gx:MultiTrack`。不跟随外部 NetworkLink；空坐标保留断点。
- 每次一个 UTF-8 文件，最多 5 MiB、30,000 个点、100 段。DTD、实体声明、异常 XML、无效经纬度和超限请求拒绝处理。
- 距离采用原始点的球面距离累加，不跨段连线，不使用图片估算距离。
- 海拔来自文件。KML 明确使用 `absolute` 时读取坐标高度；部分 GPS 导出文件省略海拔模式，但保留了高度，此时兼容读取已有高度并显示来源提示，支持 `LineString` 和 `gx:Track`。明确声明的贴地/相对地面模式仍不作为绝对海拔，`gx:MultiTrack` 的模式继承与子轨迹覆盖规则不变。缺失海拔不填零、不自动接 DEM，也不跨缺失段补曲线；兼容读取不代表已校正高程或验证垂直基准。
- 爬升/下降是相邻原始海拔差的累计，未做滤波；受 GPS 海拔噪声影响。一段海拔不完整时，该段爬升/下降显示未提供；其他完整段照常计算。
- 地形底图使用 Leaflet + OpenTopoMap。底图需要网络，失效时回退为真实坐标图并提示，不用虚构等高线替代。自定义底图配置见 `.env.example`。

格式依据：[GPX 1.1](https://www.topografix.com/GPX/1/1/)、[KML 高度模式](https://developers.google.com/kml/documentation/altitudemode)、[OpenTopoMap 使用说明](https://opentopomap.org/about#verwendung)。

## 后台变化

- 控制台加入 Debug 摘要与独立 Debug 区域，提示重名组、地点待核实记录。
- 删除“足迹管理”和“协会设置”导航与设置表单。旧 `/admin/footprints` 跳到活动管理，旧 `/admin/settings` 跳到控制台。
- 重名比较先规范化 Unicode、首尾/重复空格和大小写；只比较未归档路线。自动路线命名顺序为手填关联路线名、文件路线名、活动标题。
- 选择保留版本留下处理时间、管理员标识、原路线 ID 及胜出 ID。之后更新活动轨迹不会覆盖已经确认保留的路线版本。
- 仍有活动或去重记录引用的路线不能直接删除；删除活动时同时清理其自动关联，保留共享路线及已确认的去重历史。
- 多标签页保存时重读最新记录；同一记录被其他标签页改动时提示冲突，不覆盖已完成的去重结果。

## 已部署服务与待完成验收

本地 API 为 `/api/tracks/convert`，正式 Worker 使用相同解析和定位核心，须设置 server-only 的 `SUPABASE_URL` 与 `SUPABASE_PUBLISHABLE_KEY`。它向 Auth 校验用户，且仅接受可信 `app_metadata.role` 为 `leader` 或 `admin` 的账号；生产环境不能通过查询参数开启本地预览。

后台云端活动保存、去重、删除使用已迁移的原子 RPC，可读来源见 [route-deduplication.sql](route-deduplication.sql)。路线 RPC 部分不改变 `content_items` 表结构，也不操作旧 `chuanheng` schema；不要对现存函数重复执行 CREATE。上传转换不自动发布。用户选择先上线自行注册并确认邮件，再对真实 Auth UUID 赋 admin；旧会员表的 admin 记录不自动获得新站权限。

Worker 已成功部署并通过公网 HTTP 验收；`npm run deploy` 先执行正式构建，可用于后续授权重复发布。邮件回跳管理面核对、真实账户上传和内容管理、Worker 实际 CPU/内存及文件上限仍待验证。底图/边界来源记录继续保留，HTTP 检查不代替这些项目的验收。
